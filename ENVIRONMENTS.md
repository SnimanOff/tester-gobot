# Управление тестовыми средами

Каждая среда запускает отдельный экземпляр управляющего бота и две базы Redis в собственном проекте Docker Compose. У каждой среды свои сети и тома. Каждый загруженный дочерний бот запускается в отдельном контейнере `<проект>-child-<номер>` в сети `<проект>_children`, где из сервисов доступна только `child-redis`. Контейнер получает ограничения памяти, процессора и числа процессов, работает от пользователя 10001 без привилегий и удаляется после остановки. Для создания контейнеров управляющему боту передаётся сокет Docker, поэтому он фактически получает права администратора Docker на хосте.

Для работы нужны Docker с Compose и Go. Команды ниже выполняются из корня проекта. Для каждой среды нужно подготовить отдельный файл переменных по образцу `environment.env.example` и указать в нём токен управляющего бота, идентификатор владельца, пароль Redis и при необходимости `CHILD_BOTS_LIMIT` - наибольшее число дочерних ботов (по умолчанию 3). Каждому дочернему боту соответствует своя база Redis. У одновременно работающих сред управляющие токены должны различаться между собой; то же относится к дочерним токенам. Храните заполненные файлы вне каталога проекта и не добавляйте их в систему контроля версий. Переменные доступны пользователям, имеющим доступ к Docker daemon.

Запуск среды с именем `alpha`:

```text
go run ./cmd/environments up alpha ../alpha.env
```

Другие действия с той же средой:

```text
go run ./cmd/environments status alpha ../alpha.env
go run ./cmd/environments logs alpha ../alpha.env
go run ./cmd/environments stop alpha ../alpha.env
go run ./cmd/environments down alpha ../alpha.env
```

Дочерние боты создаются как управляемые боты Telegram (Bot API 9.6). Для этого в @BotFather у управляющего бота нужно включить управление другими ботами. Команда `/newbot` показывает кнопку создания бота; после подтверждения в Telegram управляющий бот получает обновление `managed_bot`, запрашивает токен методом `getManagedBotToken` и присваивает боту номер. Архив отправляется управляющему боту: без подписи он запускается на первом свободном боте пользователя, подпись с номером или @username выбирает бота. `/status` показывает всех дочерних ботов, `/stop` останавливает все свои, `/stop 2` - бота с номером 2.

`stop` останавливает контейнеры. `down` удаляет контейнеры и сеть, не запрашивая удаление томов. Повторный `up` использует сохранённые тома. Для каждого действия требуется файл переменных. Программа проверяет формат имени среды; проверка уникальности токенов не выполняется.



# Развёртывание в Docker Swarm

Файл `docker-stack.yml` описывает стек из управляющего бота и двух Redis. Сеть `children` создаётся как overlay с возможностью подключения обычных контейнеров; дочерние контейнеры создаются на том узле, где работает управляющий бот. Перед развёртыванием нужно собрать образ `docker build -t testbot-platform:local .`, подготовить переменные `TESTER_BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `REDIS_PASSWORD` в окружении процесса и убедиться, что узел Docker уже состоит в Swarm. Затем стек можно создать командой `docker stack deploy --resolve-image never -c docker-stack.yml testbot`, просмотреть командой `docker stack services testbot` и удалить командой `docker stack rm testbot`.

Локальный образ и локальные тома проверены только на одном узле. Для нескольких узлов требуется отдельно обеспечить доступность образа и продумать размещение постоянных данных; перенос и отказоустойчивость здесь не проверены. Токены и пароль передаются в переменных сервисов и доступны администраторам Docker. Ограничения контейнеров снижают риск, но доступ управляющего бота к сокету Docker остаётся.

Файл `.github/workflows/test.yml` задаёт запуск тестов и сборку образа при push и pull request. Ручной `workflow_dispatch` дополнительно предусматривает развёртывание на self-hosted Linux runner с меткой `swarm-manager` в окружении `test`; необходимы заранее настроенные секреты с именами переменных выше, Docker и Swarm manager на runner. Автоматическое развёртывание при push не настроено. Рабочий процесс в GitHub не запускался.

Проверка запуска дочерних контейнеров в Docker:

```text
go test -tags docker -run TestBotsRunInContainers ./bot/children/launcher
```
